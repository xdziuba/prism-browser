# AI tool foundation: security review

Reviewed: 2026-10-09. Scope: `prism/ai/browser_tools.*`, `page_context.*`, `accessibility_context.*`, the Chromium tab/page adapters, strict tool codec, Responses client, and AI session service. These sources have GN integration but no Chromium C++ compile or browser run yet.

| Threat | Current control | Remaining verification |
| --- | --- | --- |
| Model self-grants capability or approves its own action | `Grant`, `Approve`, `Reject`, `BeginTask`, and `Stop` are separate trusted UI entry points, not tool variants. Calls without a grant are rejected before browser inspection. Approval is tied to an internally generated, one-use action ID. | Ensure Chromium/WebUI bindings never expose these methods to page content, extension content, or model tool arguments. |
| Consequential click/type/close without consent | These tools always wait for approval. The host re-inspects the target before execution. Other host-classified consequential actions also wait. | Real DOM and navigation tests, including form submission and changed target after approval prompt. |
| Stale action gaining a new task's permissions | Task generation is checked after inspection and before issuing a ticket. Stop cancels pending actions and signals active ones. A new task cannot start until prior tickets complete. | Stress test with real Chromium threads and async operations. |
| Password or sensitive form data in context | Password/sensitive nodes are omitted; all editable form values are ignored. Audit records no tool arguments or outputs. | Verify Chromium adapter marks password/sensitive nodes and supplies a label separate from the field value. |
| Tokens and headers in visible text | Header lines, bearer tokens, known token keys, and JWT-shaped strings are redacted by a bounded scan. | This is defense in depth, not complete secret detection. Chromium network/console adapters must structurally remove authorization headers, cookies, session tokens, JWTs, and sensitive form values before any AI output. |
| AI in Incognito | Session start and message submission deny Off the Record windows; each tab/page tool inspection also checks `Profile::IsOffTheRecord()`. No grant is implicit. | Verify in a real Incognito window after browser build. |
| Unbounded untrusted content | Only visible nodes are used; node, element, text, label, title, origin, and argument lengths are capped. | Measure extraction latency and memory on real pages. |
| Stop during a browser operation | Active calls receive a cancellation signal and the audit logs its request. The tab adapter checks before each operation; the broker withholds output from any completion after Stop. | Async adapters must poll/propagate cancellation and always finish tickets; an action already dispatched cannot be undone. |
| Sensitive tab metadata in AI output | Tab list emits only session tab ID, active state, and HTTP(S) origin, capped at 200 tabs. Open/close emit typed request acknowledgements. The strict serializer allowlists fields and strips URL paths, queries, and fragments before model transport. | Compile and inspect output in the browser, including malformed origin and oversized output cases. |
| URL driven side effect | The adapter accepts only valid HTTP(S) URLs with no user info. Open is classified consequential and needs one-use user approval. | Browser test should cover malformed and credential-bearing URLs and a changed window after approval. |
| AX tree leaks protected or cross-origin data | The request uses same-origin direct descendants and a 1,000-node cap. The converter traverses root-linked nodes only, excluding hidden, ignored, editable, protected, and text-field subtrees. It reads only AX names for static text, headings, and a small interactive role whitelist; it never reads AX values. | Browser tests must verify cross-origin frames, password fields, form values, ARIA references to sensitive content, and renderer-supplied malformed trees. |
| Async snapshot blocks later tasks | The AX callback checks Stop, tab lifetime, tab membership, and navigation entry. Chromium's dropped callback wrapper invokes a failure path so the broker ticket completes. | Verify timeout and tab destruction in a browser test; callback behavior is not compiled or run yet. |
| Model grants itself power or fabricates an approval | Responses function schemas contain only six implemented tools. The codec rejects unknown names and malformed arguments. Session approval controls are separate trusted methods bound to a one-use action ID. | Verify future WebUI Mojo bindings reject calls from arbitrary web pages and extensions. |
| Network credential or cookie leakage | The Responses client uses a fixed HTTPS endpoint, no redirects, omitted cookie credentials, response-size caps, and a transient in-memory API key. The key is never sent to the model as a tool result. | Wire OS-backed credential storage; test request headers and redirects with an injected URL loader. |
| Prompt injection in page text | The model request labels tool results as untrusted, while structural redaction and browser permission checks remain the enforcement boundary. | Adversarial browser tests with instructions embedded in AX names and visible text. |

The broker still trusts the browser host's `Inspection`. The source cannot prove actual accessibility-tree redaction, semantic element validity after DOM mutation, or cancellation of Chromium callbacks until browser tests run. The model transport is source-only and has no key provider or UI entry point, so no live request has occurred. A future approved tab-open call would navigate normally through Chromium. The in-memory audit timeline is not yet persisted across browser restarts and can grow with task activity; persistence and retention limits are required before release.
