# Native Prism shell: material foundation

2026-10-14. This is the first native browser-chrome slice under ADR 0002. The
Linux source build and native media-component smoke passed; Windows, the live
AI call, and the Store update gate remain open. It does not declare Phase 0
complete.

## Design direction

The page is the content layer. Tabs, the address bar, toolbar, side panel, and
menus are the functional layer. Only the latter may carry a glass treatment;
DevTools and web content retain their standard behavior. Prism's identity is
a quiet, cool, translucent-looking navigation frame with one crisp focus
accent. Readability and familiar browser controls take priority over blur.

Use the [Apple Design Skill](https://github.com/dickwu/apple-design-skill)
review method, especially `references/hig/liquid-glass.md` ("The two layers",
"Accessibility states"), `materials.md` ("Liquid Glass"), `toolbars.md`
("Best practices"), `color.md` ("Liquid Glass color"), `accessibility.md`
("Vision", "Mobility"), and `windows.md` ("Best practices"). These are design
principles for our Chromium Views UI on Linux and Windows, not a claim of
native macOS material support. The local `liquid-glass` skill informs the
surface anatomy: a restrained fill, one top highlight, a fine boundary, and
an opaque fallback.

## Token and behavior plan

| Role | Dark fallback | Light fallback |
| --- | --- | --- |
| Window frame / inactive tabs | `#1C2932` | `#E2EBF0` |
| Active tab / toolbar | `#2C3942` | `#F5F9FB` |
| Primary browser-chrome text | `#F2F6F8` | `#21313B` |
| Secondary browser-chrome text | `#C8D5DD` | `#465C69` |
| Edge highlight | `#667E8B` at low opacity | `#FFFFFF` at low opacity |
| Focus | Chromium semantic focus color, contrast checked in both modes | same |

The first patch only establishes the opaque Linux/Windows color foundation
through Chromium's color provider. It leaves standard hit regions, keyboard
focus, tab placement, window controls, and DevTools intact. It applies to the
ordinary Chromium frame, including a Linux native GTK theme, after the native
color mixer. Installed extension and autogenerated themes, app windows,
forced colors, and high contrast retain Chromium's recipes. Follow-on
patches can shape tab edges and add a specular rim. Real backdrop blur must be
platform-aware and conditional; Linux without compositor support and reduced
transparency use the opaque palette above. Never blur web content or stack
blurred surfaces across tab strip, toolbar, and side panel.

## Verification

### Linux GTK frame decision (2026-10-14)

The first visual capture exposed a GTK-painted empty titlebar region that did
not match the Prism frame token. `FrameBackground` delegates that region to the
Linux native theme even when the browser has supplied a ColorProvider frame.
For an ordinary Prism window with no frame image, cover only the
interior of that top area with the resolved Prism frame color after GTK paints
it. Keep native frame edges and preserve GTK's paint path
for app windows, custom image themes, special frame modes, and frames whose
color does not resolve to a Prism token. This is an opaque surface correction;
it does not introduce backdrop blur or change window hit testing.

Capture the current and changed native frame on the same synthetic page in
light and dark modes. Check tab and toolbar text contrast from the actual
resolved colors, keyboard focus, a narrow window, and high contrast/system
theme fallbacks. Relink the pinned `chrome` target after upstream source
changes, then run ordinary-page, Prism WebUI, F12, and extension smoke tests.
Record observed outcomes in the feasibility report. Windows appearance and
any true backdrop blur stay unverified until tested on those platforms.
